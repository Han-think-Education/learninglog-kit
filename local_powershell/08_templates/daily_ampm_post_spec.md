# LearningLog 일일 오전/오후 블로그글 작성 양식 (GPT용 지시서)

> 이 파일을 GPT에게 그대로 주고, 아래 "입력 자료"에 그날의 소스 노트를 붙여서
> "이 양식 규칙에 100% 맞춰 오전글 1편, 오후글 1편을 만들어줘" 라고 요청하세요.
> 출력은 **그대로 .md 파일로 저장하면 발행 검수(QA 게이트)를 통과**하도록 설계돼 있습니다.

---

## 0. 무엇을 만드는가

- **하루 = 오전글 1편 + 오후글 1편.**
- 그날의 `AM_INDEX`(오전) / `PM_INDEX`(오후)에 적힌 included notes들을 **하나의 글로 통합**한다.
- 각 노트가 한 편의 `## N. 소제목` 섹션이 된다. (노트 4~5개면 섹션 4~5개)
- 과거 글은 **절대 수정하지 않는다.** 새 날짜만 새 파일로 추가한다(누적).

## 2. 반드시 지켜야 하는 규칙 (어기면 검수에서 차단됨)

1. **제목**: `오전 학습 | 핵심 주제 한 가지` 또는 `오후 학습 | 핵심 주제 한 가지` 형식으로 짧게 쓴다. 날짜는 front matter의 `date`가 담당하므로 제목에 반복하지 않는다. `오늘 오전`, `오늘 오후`, `정리했습니다`, 여러 문장, 줄바꿈, `학습 노트`는 쓰지 않는다.
2. **플레이스홀더 금지**: `정리 필요.` 같은 빈칸 채움 문구를 **절대** 남기지 말 것. 모든 섹션을 실제 내용으로 채운다.
3. **`## 목차` 섹션 필수**: 글 맨 위(frontmatter 다음)에 목차. 각 `## N. 제목`마다 링크 한 줄.
4. **`## 총평` 섹션 필수**: 맨 아래에 총평. 하위에 `### 오늘 ... 배운 것`, `### 다음에 조심할 것`, `### 다음 복습 주제` 3개.
5. **본문에 `---`(수평선) 금지**: 단, **목차 바로 아래 한 줄만** 허용(골격 참고). 그 외 어디에도 `---` 줄을 넣지 말 것.
6. **`source_id:` 등 내부 메타데이터 금지**: frontmatter에 `source_id`, `note_date`, `mode`, `model` 같은 키 넣지 말 것. (위 골격의 키만 사용)
7. **굵은 메타데이터 금지**: 본문에 `**제목**:`, `**날짜**:` 같은 줄 금지.
8. **코드펜스 짝 맞추기**: ```` ``` ```` 는 항상 열고 닫기. 들여쓰기된 펜스는 같은 들여쓰기로 닫기.
9. **빈 출력 주석 금지**: `# 출력:` 처럼 뒤가 비어있는 줄 금지. 결과를 보여주려면 실제 값을 적는다.
10. **최상위 `## 제목 중복 금지**: 같은 `## 제목`을 두 번 쓰지 말 것(`### 소제목` 반복은 괜찮음).

## 3. 목차 앵커(링크) 만드는 규칙

`## 1. SQLTools 실행하기` 라는 제목의 앵커는 다음 규칙으로 만든다:

1. 전체 제목 텍스트를 소문자로.
2. 영문/숫자/한글/공백/하이픈을 제외한 기호 제거 (예: 마침표 `.`, 작은따옴표 `'` 삭제).
3. 공백을 `-` 로 변경.
4. 앞에 `#` 붙임.

예시:
- `## 1. SQLTools 실행하기` → `#1-sqltools-실행하기`
- `## 3. ERD와 Crow's Foot 읽기` → `#3-erd와-crows-foot-읽기` (작은따옴표 삭제)
- `## 총평` → `#총평`

목차 줄 형식:
- 번호 있는 섹션: `- 1. [SQLTools 실행하기](#1-sqltools-실행하기)`
- 번호 없는 총평: `- [총평](#총평)`

## 4. 섹션 구성 가이드

- included notes의 각 노트 1개 = 글의 `## N. 소제목` 1개.
- 각 노트의 `what I learned / what confused me / corrected understanding` 흐름을
  `### 무엇을 배웠나 / ### 헷갈렸던 점 / ### 정리된 이해` 로 자연스럽게 옮긴다.
- 코드 블록(SQL/Python 등)은 **그대로 유지**하고 언어를 표시(```` ```sql ````, ```` ```python ````).
- 초보자가 이해하기 쉬운 비유·설명을 보존한다.
- `### 무엇을 배웠나` 등 하위 제목 구성은 권장안이며, 내용이 자연스럽게 채워지면 약간 달라도 된다.
  단, **2번 규칙(플레이스홀더 금지)과 3·4번(목차·총평)** 은 반드시 지킨다.

---

## 5. 공개 정책 처리

- 노트의 `public_policy` 가 `public` 이면 그대로 사용 가능.
- `partial-public` 이면: 노션 내부 URL, 개인 워크스페이스 정보, 강의 내부 경로, 화면 캡처 원문, DB 파일 재배포 관련 내용을 **일반화/삭제**한 뒤 사용.
- `internal-only` / `private` 노트와 `*_INDEX` 노트 자체는 **글에 넣지 않는다**(분류 참고용).
